# 部署安全检查

仓库默认配置用于受控的本地开发。示例密码、API Key 占位符和测试凭据不是可用于生产的秘密；它们公开可读，不能提供生产访问保护。

## 公开服务前

- 为数据库、对象存储、图数据库、JWT 和管理接口分别配置独立随机凭据。真实值不要提交到 Git，也不要放进前端代码或日志。
- 默认 `docker-compose.yml` 的端口映射未限制为回环地址。应按部署环境显式限制数据库与管理端口的监听地址和网络访问范围。
- Elasticsearch 示例关闭了安全认证，Kafka 示例使用明文监听。未完成鉴权、网络隔离和必要的 TLS 配置前，不应开放到公网。
- 核对反向代理、上传与沙箱边界，并确认备份、恢复和依赖安全检查。通过单元测试不等于生产安全验收。

## 配置文件与版本控制

`config/config.yaml` 和 `config/config.docker.yaml` 是受 Git 跟踪的示例配置。按 README 填入真实 API Key 后，文件会包含本机秘密，提交前必须检查 `git diff`。不要把修改过的配置或环境变量文件上传为调试附件。

现有环境变量入口包括 `JWT_SECRET`、`GITHUB_TOKEN` 和 `PPROF_ADMIN_TOKEN`；其他配置项以配置加载器当前支持的方式为准，不假定所有 YAML 字段都支持环境变量覆盖。

若真实凭据曾被公开，先在签发服务撤销或轮换，再处理仓库内容与历史。仅删除当前文件不会清除旧提交、其他公开分支或他人副本。

## 本次整理范围

公开文档整理不会自动修改已经运行的服务、网络监听或现有密码。上线前应针对实际部署完成上述配置与验证。
